# 日本語長文の「文字化け混入」を復旧する方法（2026-10-01 実測）

## 現象

`Write` / `Edit` で長い日本語 Markdown を書くと、句読点付近や文の接続部に
**別スクリプトのトキンが混入**する。実測例（2021 自由部門 発表 5/6 の要約）:

- ラテン/英単語の混入: `TIMING` `conundrum` `implomatous` `recognize` `CIDENT` `KEY` `cognizant`
- 漢字の誤り: 工夫→`功夫`/`工天`、構造→`結構`、配慮→`配慷`、コード→`コーード`、Toronto→` toman`
- **アラビア文字が漢字の間に混入**: `使える → 使える Integrating`（U+0627 U+0631 U+0639）
- 中国語/韓国語: `那里` `与众不同` `이미`
- Markdown の太字記号 `**` が本文中に散らばる（`取り除*いている*`）

**重要**: Cleanup した_edit も新たな混入を作る。1 回目の Write → Edit 1 → Edit 2 と
直すほど混入が増えていく場合がある。

## 検出（必ず実行）

```bash
# 1. ラテン・ギリシャ・Кирилл・アラビア・ methodologies  Hungul・全角括弧の混入
grep -nP '[\x{0600}-\x{06FF}\x{0400}-\x{04FF}\x{0370}-\x{03FF}\x{AC00}-\x{D7AF}\x{0590}-\x{05FF}\x{0E00}-\x{0E7F}\x{FFFD}]' <file>

# 2. 出現ラテン語を列挙し、許可リスト外を洗い出す
grep -noP '\b[A-Za-z]{3,}\b' <file> | awk -F: '{print $2}' | sort -u | tr '\n' ' '

# 3. 漢字/かなとラテンの隣接（混成文字の検出）
grep -nP '[ぁ-んァ-ヶ一-龥][A-Za-z]{2,}|[A-Za-z]{2,}[ぁ-んァ-ヶ一-龥]' <file>

# 4. 全文 Read を目視（上の 3 つでは検出できない「日本語の誤った語」のみ残る）
```

## 復旧手法: codepoint 組み立て（最も有効）

**直接日本語を書くと誤るが、ASCII の 16 進数は絶対に誤らない。**
Python で `chr(int(h, 16))` として組み立てる。

```python
C = lambda *xs: ''.join(chr(int(x, 16)) for x in xs)
# 必要な語だけ hex で持つ
ln = lines[41]
ln = ln.replace(C('9664', '3044', '3066'), C('9664', '3044', '3066', '2a', '2a'))  # 取り除いて -> 取り除いて**
```

- 16 進数は ASCII なのでトキ化管理の影響を受けない（実測で 100% 成功）
- 一般的なコードポイント:
  - 工夫 `5de5 592b` / 構造 `69cb 9020` / 配慮 `914d 616e` / 意識 `610f 8b58`
  - コード `30b3 30fc 30c9` / という `3068 3044 305f` / といった `3068 3044 3063 305f`
  -  Easier `3084 3059 3044` / 分 `5206` / 取り分け `53d6 308a 5206 3051`
- **必ず `unicodedata.name()` で意味を確認してから使う**
  ```python
  import unicodedata as ud
  print(ud.name(chr(0x9020)))   # -> CJK UNIFIED IDEOGRAPH-9020
  ```
  ただし `name()` は意味を返さないので、**印字して目視**するしかない。
  → 実行前に `print(''.join(chr(int(h,16)) for h in ...))` で 1 行出力して確認する。

## その他の tactic

- Cleanup は **スクリプトファイル**（`/tmp/opencode/<name>/fix.py`）に書いて実行する。
  `python3 -c "..."` インラインは日本語文字列のクォート地狱で失敗しやすい。
- 行全体を 1 から作り直すときは「行インデックス」で `lines[41] = ...` と代入する
  （`str.replace` のク Boundaries 判定は混入文字があると必ず `MISS` する）。
- 境界が分からないときは `repr(line[i:i+8])` と `[hex(ord(c)) for c in seg]` でDump する。
  **`index()` は「ほぼ一致」になることがある**ので必ず `assert` / `print` で確認する。

## 教訓

- cleanup  courtesies ごとに再検査する。1 回の Write では絶対に終わらない。
- 太字 `**` は装飾なので、復旧が_posts墜ったら**属性として落とす**ほうが早い
  （`独自`+`工夫` の 1 行を作り直すとき `**` を入れずに書き直す）。

## 追加知見（2026-10-05 実測・最重要）

**かなの code point は記憶で書けない。必ず Python に印字させて表を取り直すること。**

- 記憶で hex を書くと静かに誤る。実測した誤り:
  - 体 に `4E53` → 実際は `4F53`（`4E53` は「乒」）
  - う に `3086` → 実際は `3046`（`3086` は「ゆ」）
  - も に `308E` → 実際は `3082`（`308E` は「ゎ」）
  - べ に `3073` → 実際は `3079`（`3073` は「び」）
  - 語順を逆に並べる（`となみす` ← `とみなす`）、hex 変換し忘れ（`須` 抜け）
- **`unicodedata.name()` の assert では誤漢字を検出できない**
  （`4E53` でも `CJK UNIFIED IDEOGRAPH-4E53` と返って必ず通る）。
  assert は桁数・文字数・借用断片の typos 検出だけに使う。
  **漢字・かなの正誤は印字して目視する以外に方法がない。**
- 表を毎回取り直すコマンド:
  ```bash
  python3 -c "
  for lo,hi,l in [(0x3041,0x309F,'HIRAGANA'),(0x30A0,0x30FF,'KATAKANA')]:
      print(l); print(' '.join('%s=%04X'%(chr(c),c) for c in range(lo,hi+1)))"
  ```
- 最も安全な戦略は **全行再構築ではなく、既存の正しい断片を anchor として差し替える**こと。
  `line.index("ASCIIアンカー")` で prefix を切り、hex 組み立ては**欠けた語だけ**を埋める。
  新規に日本語を書く量そのものが混入リスクなので、既存行の 1〜2 語だけ直すのが安全。
- 書き込み前に `print` してから `input("write? [y/N]")` で確認する段をスクリプトに内置すると、
  誤字がファイルに焼き込まれるのを防げる。
- 1 回の Write では終わらない（実測 4 往復で収束）。

## 混入は「ファイル」だけでなく tool 引数（talk-delegate / talk-post_post）でも起きる（2026-10-07 実測）

NextCloud Talk の venue で role へ渡す本文を `talk-delegate` / `talk-post_post` に
inline で書いたとき、**ファイル書き込みと同じ混入が chat メッセージに起きた**。

実測した混入:

- 漢字 1 文字の誤り: `役割で分aked構成`（`けた` → `ked`）、`ステークホルダー`
- 別スクリプトのトークンの混入: `判断Swapse perceptible 之处`、`内容Wiseは`、`別の分割不会有ければ`
- 英単語の途中差し込み: `MmargeUp`、`athi 卡片`

**混入監査（`tools/audit-jp-mixed-chars.py`）はファイルにしか掛からない。**
chat メッセージは監査されないので、気づかないまま投向される。

### 対策

1. **role へのメッセージは短くする。** 長いと混入の確率が上がる
2. **正となる長い内容はファイルに書いて、メッセージは「ファイルを見てください」だけにする**
   （実装の詳細・表・原文をファイルに置き、delegate には要約だけ渡す）
3. 混入したら**訂正メッセージを 1 通だけ**送り、さらに長い訂正は送らない
   （訂正文を長くするとその文自体が混入する。2 通目の訂正で悪化した実測あり）
4. 検証済みのファイルパスをメッセージに含めると、受け手は chat 文ではなく
   ファイル（監査済み）を見るので、混入が実質的に無害になる
